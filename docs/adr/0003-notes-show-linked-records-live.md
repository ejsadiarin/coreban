# Notes show their linked record live

A note that links a record (a reminder, a card, or a corefinance expense or income) keeps no content of its own. It stores only the record's kind and id, and the feed shows the record as it is now. Editing the note edits the record. A record has at most one note, and only records captured through the feed have one. The note saves a snapshot of the record only once the record is gone: when it is deleted, or when the feed first finds it missing. An archived note keeps showing that snapshot.

We rejected two-way sync, where the note keeps its own text and an edit on either side is copied to the other. That makes two copies, and a half-failed edit (common on a phone, and certain across two services) leaves them disagreeing with no way to tell which is right. We also rejected frozen notes ("Reminder created", never updated). They let the feed show a time or amount that is no longer true.

**Consequences**: coreban stores ids from corefinance without checking them. It can't, since it has no credential of its own to call corefinance. The web reads expenses and incomes straight from corefinance for each screen of the feed, so corefinance needs an endpoint that fetches several by id. Archiving a note that links across services takes two requests that can't happen together, so the record is always deleted first. If the second request fails, the note still points at a record that no longer exists. The feed reads that as deleted the next time it loads, so the half-finished delete heals itself. Archiving a note archives a linked card, which can be recovered, but deletes a linked reminder, expense or income for good, after the owner confirms.
