# Attachments live in object storage, uploaded straight from the phone

A plain note can carry up to ten images or videos. Their bytes live in S3-compatible object storage (Cloudflare R2 today), never in Postgres: the database is Neon, whose free storage is about 0.5 GB, and a few dozen videos would fill it. Postgres keeps one row per attachment (its note, storage key, type and size). coreban hands the web a short-lived signed link to upload each file straight to the bucket, and a fresh signed link each time the Feed shows it, so files never pass through the gateway or coreban. Only the links expire; a file lasts as long as its note. Images are re-encoded on the phone to WebP of at most about 2048 px and 5 MB, which also strips their location data, and the original is not kept. Videos are stored as uploaded, at most 25 MB, with a poster frame the phone takes at upload time.

We rejected passing uploads through the gateway: nginx refuses bodies over 1 MB by default and the gateway drops requests after 10 seconds, both right for an API and wrong for a 25 MB video on mobile data. We rejected self-hosting storage on the homelab for now: the code speaks only the S3 API, so moving to Garage or MinIO later means copying the files and changing configuration, not rewriting anything. We rejected keeping original photos: a camera photo is 4 to 8 MB against about 0.5 MB compressed, and the gallery on the phone already has it.

**Consequences**: the database and the bucket can't change together. A note is posted only once all its files are uploaded, so an upload that never becomes a note leaves a file with no row, which a sweep deletes. Permanently deleting a note deletes its rows first and queues their files for deletion, retried until the bucket confirms. Uploads count toward a per-owner quota (`ATTACHMENT_QUOTA`, 5 GB), including archived notes and unfinished uploads; admins have none. Demo guests can't upload, so the gateway now marks a guest session with a `guest` scope, as it marks admins with `admin`. A HEIC image can't be decoded by Chrome on Android, so it is refused rather than stored uncompressed. An admin's targeted read of another owner's Feed shows that their attachments exist, never links to them. Files shared from another app wait in the chat box to be posted, unlike shared text, which posts at once.
